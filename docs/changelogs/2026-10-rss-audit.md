# RSS 分配决策审计（可观测性升级）

## 范围

不修改空闲资源公式、平滑加权轮转、准入阈值、候选配置、接受/拒绝规则、额度或辅种行为。仅在原决策路径同步复制标量输入，通过 INFO `RSS_ALLOCATION_EVENT` 输出脱敏结构化事件。审计创建、回调或序列化失败不能改变准入结果，不额外请求下载器。

独立监控接收所有 clientId 的 RSS 事件，不再受原 BHS/HDD 删种监测目标列表限制。第一阶段不新增 RBX/VPS 的持续 qB 流量采样，不作收益归因或反事实承诺。

## 事件协议 v2

- `runtimeId` 为进程随机标识，`decisionId` 为进程内递增唯一标识；`eventId = decisionId:stage`。
- `stage=decision`：原候选 ID、最终选中目标/lease、RSS ID、种子 hash/真实 hash（已知时）、大小、发布时间/发现时间、模式、路由、规则 ID/优先级/指纹、配置指纹、RSS 与分配器限制。
- 每个参与候选保存当时在线/运行实例状态、成功快照和请求开始时间、年龄/新鲜度、容量、即时速度与 EMA、实际同机聚合速度、当前下载数与全部 RSS 待确认预留、空间保底/写入预留、I/O 已知值、余量、权重、归一化份额及轮转前后信用。共享组保存精简成员输入，不保存任务列表。
- 不合格候选保留检查停止前已经读取的输入及精确排除原因；未知不补零。强制定向时保留列表外目标，普通候选标为 `forced-not-considered`，不冒称资源不合格。
- `stage=submitted`：在 POST 之前记录最终校验的精简输入与等待时间；不能把最初选择快照冒充稍后的最终状态。
- `stage=result`：accepted / uncertain / cancelled / rejected / filtered / interrupted，含提交标记、耗时、标准化原因和是否属于未发送的公平信用退还。accepted 由正向 API 钩子确认，不因随后数据库失败反转。
- 资源预检查无目标时，在原有整批拒绝之前为每颗种子输出 preflight-rejected 与 result；保存的是预检查当时的矩阵、时间及 1 字节探测语义，不是假装执行了按实际种子大小的最终选择。
- 免费/HR/接受规则等准备阶段拒绝输出 filtered。最长休眠、额度、RSS 抓取/冻结等更早过滤仍沿用原有记录；它们不属于本次完整分配决策覆盖，不能把审计总量当成全部 RSS 条目数。

## 隐私、成本和边界

不写 URL、下载链接、Cookie、密码、保存路径、种子名、完整规则代码或完整种子列表；用 RSS ID、hash、rule/config 指纹定位。独立监控可从现有配置读取限长的显示别名，不复制连接配置；HTML 统一转义。

事件最多 256 个候选、512 KiB；超限显式 `snapshotTruncated`，不用于完整候选公平分析。信用按原算法同步采集，浮点尾差保持原值。审计结果只是正向 API 接纳，不保证 qB 最终完成创建或获得上传收益。

独立监控新增 RSS 专用明细/分钟聚合表，沿用单写者、轮转恢复与事务日志偏移；不覆盖原删种和流量表。按 decision/lease+stage 去重，兼容乱序和重复读取。v2 比旧格式丰富时替换旧条目并修正聚合，避免新旧日志双计。

旧 `RSS分配` / `RSS添加结果` 可以补采为 `legacy-selected-only`；缺少 RSS ID、hash、未选目标或结果路由时保持未知，不能从稍后的状态推测。已有已消费日志不会靠重置主偏移补读，使用持有同一 collector 锁的 RSS-only 回填工具。

原始明细跟随 7 天/磁盘压力裁剪，同时默认额外限制 RSS 原始载荷 128 MiB；去重索引头默认最多 250000 条，分钟聚合按 90 天保留。真实保留时间受全局 2 GiB 与剩余磁盘约束，不承诺固定天数；被清理的明细保持显式缺失，不制造空快照。

报表分别列出任务/目标、自由/forced/辅种、选择/提交/结果、无结果/在途、排除原因和完整已提交矩阵的累计权重曝光。统计不是逐次“最大权重应当获胜”判定；起止信用、退还、候选集和运行实例改变都会影响短窗份额。分钟总量起点向下取整，原因/曝光最多扫描仍保留的最近 20000 个决策，必须显示该口径。
